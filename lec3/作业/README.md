# 机械臂作业

本文件夹存放作业的 Python 代码、配置及说明，包括 SCS215 舵机编号、连接检查、交互式校准、四姿态记录和六关节控制。运行环境为 `lerobot`，代码仅使用 pyserial 和标准库。

## 每次给一只舵机编号

1. 断开舵机电源，支撑好已组装的机械臂。
2. 将当前要编号的舵机直接连接到控制板，断开它与其他舵机的连接。一个编号响应不代表一定只有一只：同 ID 的多个舵机可能无法由扫描区分。
3. 接好 USB 和适合这批 SCS215 的电源，上电后运行下面命令，输入目标编号。
4. 看到“成功”和读回验证结果后，在对应舵机上贴好编号。断电换下一只，重复运行。
5. 六只设置完后，断电重新连接总线，再整体查询验证。

```powershell
& 'D:\miniconda\envs\lerobot\python.exe' 'D:\Desktop\CS\具身智能\lec3\作业\set_id.py'
```

| 编号 | 关节 |
|---|---|
| 1 | 底座旋转 shoulder_pan |
| 2 | 肩部抬升 shoulder_lift |
| 3 | 肘部弯曲 elbow_flex |
| 4 | 手腕弯曲 wrist_flex |
| 5 | 手腕旋转 wrist_roll |
| 6 | 夹爪 gripper |

也可在命令末尾加 `--id 3` 直接指定编号；加 `--check` 仅扫描并读取状态。串口默认按原 USB 转接板的序列号查找，如更换转接板，可使用 `--port COM9` 指定实际端口。程序按 1 Mbps 通信，无响应时请先核对供电、线材和原波特率。

## 编号程序原理

逐个 PING ID 0～253，发现唯一响应编号后读取型号字节、SCS 字节序标志、位置及状态。关闭扭矩（0x28 写 0），解锁 EEPROM（0x30 写 0），修改 ID（0x05），再通过新 ID 锁定 EEPROM（0x30 写 1）。最后读取新编号、锁和扭矩状态，并确认旧编号不再响应。若目标编号已经是当前编号，则跳过 ID 写入。

包头为 FF FF，校验和为从 ID 至最后一个参数的字节和取反后保留低 8 位。程序会校验应答包并在异常时中止；没有位置控制或扭矩开启指令。成功记录追加保存到 `id_setup_log.jsonl`，断电保持情况仍需重新上电查询确认。

此脚本用于用户确认的 SCS215，不适用于 STS3215；后者的 EEPROM 锁地址不同。校准和控制代码也必须按实际 SCS215 的参数实现，不能直接使用 SO-101 文档中 STS3215 的参数。

关节编号参考：[Hugging Face SO-101 文档](https://huggingface.co/docs/lerobot/main/en/so101)。

## 两端点校准：calibrate.py

本次采用自定义范围：先把六个关节都摆到各自希望的 0 端，统一记录；再按 ID 1～6 分别摆到各自希望的 1 端，每个关节单独按回车记录。六个 1 端不必同时达到，不要求摆官方四个姿态。这里的 0 和 1 是比例，不是原始读数 0 和 1023。

```powershell
& 'D:\miniconda\envs\lerobot\python.exe' 'D:\Desktop\CS\具身智能\lec3\作业\calibrate.py'
```

1. 六只保持串接，固定底座并托住机械臂。程序检查六个关节在线并显示位置；按回车后关闭扭矩。
2. 第一阶段：将所有关节摆到希望定义为 0 的起点，保持稳定，按一次回车记录六个读数。
3. 第二阶段：按提示调整 ID1 到它的 1 端，摆稳后回车，只记录 ID1。随后依次记录 ID2～ID6 的 1 端，共按六次回车。每次只要求当前关节稳定且端点留有余量，其他关节可以移动来避让；已记录的终点不会被后来移动覆盖。
4. 查看每个关节的 0、0.5、1 对应读数和提示，回车保存 `calibration.json`。已有文件时，输入 `overwrite` 用本次完整记录替换，仅保留当前一份；q 或 Ctrl+C 取消，旧文件保持原样。

等待回车期间，尚未记录 1 端的关节会持续采样，保留从最初 0 点到各自 1 点的数值路线；当前页面只显示、检查当前关节的端点。这样，即使调整其他关节时顺带移动了它，也不会漏掉读数跨界。已完成关节的轨迹停止更新。若当前关节五次读数还不稳定，会要求托稳后再次回车；若其采样中断或变化太快，会要求重采。退出后扭矩保持关闭，需要手动托稳放好，不会自动复位。

### 方向和数值跨界

所有关节（包括夹爪）都以原始读数增大为正方向；从外面看到的顺/逆时针取决于观察方向和安装。程序不会为了让数字大小顺序一致而交换用户定义的 0、1 端点。

原始读数范围按 SCS215 的 0～1023 处理，共 1024 个数。没有跨界时，`目标位置 = round(起点 + 输入比例 × (终点 - 起点))`。例如两端为 300、700，输入 0.5 对应 500。

若持续采样观察到正向的 `950 → … → 1023 → 0 → … → 100`，会将终点展开为 `100 + 1024 = 1124`，跨度为 174。纯数值插值为 `round(950 + 输入比例 × 174) % 1024`，不会把这次移动判成负方向。

但**数值展开不等于解决传感器盲区，也不保证舵机能按该路径闭环运动**。SCS215 使用电位器反馈，不是完整一圈的连续角度编码器；采到跨界或反馈边缘时，会保存 `requires_boundary_resolution: true`。控制程序现在允许规划跨界路线，按展开计数分段下发，并连续展开反馈：`1023→0` 记为 +1，`0→1023` 记为 -1。不能只发送取模后的终点，就假定固件会选择预期路线；每段都核对实际方向，若固件反向执行或停滞，会卸力停止。端点采集保留 20 个计数的余量只是采集设置，控制器并不因此把原始读数 0 或 1023 判为无效。

### 保存内容与当前进度

当前校准文件保存六个关节最新确认的两个端点、跨度、角度零位和通信信息，旧采样摘要已清理。ID3 范围为 319～903；ID5 重装后的范围为 400～976，角度零位为 688。`zero_pose_raw` 和 `one_positions_raw` 分别列出各关节端点，经过单关节更新后不表示曾经同时采集到的姿态。它定义的是用户选择的使用区间，不是机械臂的最大活动范围；分别可达的端点组合后不一定可达。

校准程序只写入关闭扭矩指令，不修改编号、硬件限位或目标位置。删除文件中的历史参数不会改变舵机内部参数；控制程序会实时查询硬件，而不是依赖校准时的旧快照。`motion_tested` 为 false，表示此次更新后的组合尚未实机验证。

当前仅保留 Middle；其 ID1～ID6 原始目标为 `[383, 683, 641, 649, 688, 112]`，其中 ID5 使用用户确认的新零位，其他关节沿用之前的 Middle。其余预设已清除，需要重新录制。参数简表见 `../../settings/servo_info.json`；日常只读观察推荐运行 `../../settings/check_position.py --id 5`，该版本不保存测量文件。

## 四个姿态预设：record_poses.py

在已有端点范围上，额外记录 [官方 follower 四张图](https://huggingface.co/docs/lerobot/main/en/assemble_so101#calibrate) 对应的 Middle、Zero、Rotated、Rest。每个姿态保存六个 0～1 的比例，排列顺序为 ID1～ID6，总共 4×6 个值。这里只借用四张图的姿态，不执行官方 STS 舵机的中位重设，也不改变 SCS215 的现有端点范围。

```powershell
& 'D:\miniconda\envs\lerobot\python.exe' 'D:\Desktop\CS\具身智能\lec3\作业\record_poses.py'
```

启动后托住机械臂，回车关闭扭矩；按 Middle → Zero → Rotated → Rest 顺序摆好整条手臂，每次按回车记录六个关节。Rotated 在机械臂右侧，夹爪张开。四次都完成后回车保存，会向 `calibration.json` 追加 `poses.middle`、`poses.zero`、`poses.rotated`、`poses.rest` 四个数组；原有 `joints` 和采样记录不变。取消或通信失败时不写文件。已有姿态时，确认保存会更新这四组，不另存历史备份。

Middle 不一定是六个 0.5，官方 Zero 也不等于你定义的六个 0。比例按 `((当前位置 - zero_position) % 1024) / span_raw` 换算。超出你记录的区间时会要求重新摆放；最多 3 个计数的端点抖动可以按最近端点记录，程序会明确提示，实测读数也会保存。

`pose_recording` 保存关节顺序、实测读数、端点抖动修正和当前端点的摘要标识，便于核对。若修改端点，旧比例就可能不再指向原姿态；查看函数会检查标识。重新运行 `calibrate.py` 并覆盖端点文件会清除姿态预设，需要重新录制。

查看已保存的比例（不连接串口）：

```powershell

& 'D:\miniconda\envs\lerobot\python.exe' 'D:\Desktop\CS\具身智能\lec3\作业\record_poses.py' --show middle
```

`load_pose_targets("middle")` 可取得六个原始目标值；该函数只换算数据，不发送指令。需要运动时使用下方的 `control_arm.py`。姿态采集程序不会主动转动。四个预设只是目标姿态，不包含到达它们的避碰路径；本次记录不等于已经验证自动复位。

## 六关节控制：control_arm.py

直接运行进入交互输入：

```powershell
& 'D:\miniconda\envs\lerobot\python.exe' 'D:\Desktop\CS\具身智能\lec3\作业\control_arm.py'
```

输入 `middle`、`zero`、`rotated`、`rest` 中的一个名字，或者六个比例，例如 `0.5 0.5 0.5 0.5 0.5 0.5`；也支持逗号分隔或 JSON 数组。六个值依次对应 ID1～ID6。每次输入后都重新读取六个当前位置，用本次校准范围换算起点比例，不先回到 0 或任何预设。

运动范围只采用 `calibration.json` 中这次保存的六组 0/1 端点。首次运行请托稳机械臂：发现舵机内部还有历史角度限位时，程序先关闭六只扭矩，逐只解锁 EEPROM，将地址 0x09 起的上下限四字节写为 `00 00 03 FF`，即完整原始范围 0～1023，读回确认并重新锁定。已是该范围的舵机不重复写 EEPROM。上下限不能都写 0，那会进入 SCSCL 的 PWM 模式。软件仍只下发校准端点之间的目标，并未把用户运动范围扩成整个原始量程。`--check` 和 `--dry-run` 均不会执行这一步。

配置后程序重新测量当前位置，先将旧目标覆盖为当前读数，再开启扭矩。路线按校准时的展开计数拆成小段，普通段每次最多推进 64 个计数；每一段用一条 SYNC WRITE 包同步写入六个目标，已到终点的关节保持位置。位置、时间、速度按 SCS215 高字节在前编码；时间为 0，六只速度参数均为 `SPEED = 100`，可修改文件顶部或用 `--speed 100` 指定。相同参数不保证负载下实际速度完全相同，也不保证行程不同的关节同时到达。

跨界时，目标由本圈 1023 接到下一圈 0，反向同理。旧的 20～1003 等硬件范围也会在运动前统一放宽。反馈比较使用展开计数，不再用普通数字的大小误判跨界为偏离路线。

到位后继续保持扭矩，可继续输入下一个目标。`q` 退出但保持当前姿态；托稳机械臂后输入 `off` 关闭扭矩。运动时 `Ctrl+C`、通讯异常、明显偏离路线、长期无进展或超时会尝试关闭六只扭矩；卸力后机械臂需要手动支撑。

控制台会显示当前第几段及六个本段目标；每段要求六只均在目标 6 个计数以内，连续位置样本覆盖至少 0.25 秒、波动不超过 3 个计数，再进入下一段。起点也通过连续位置样本检查稳定性。本批舵机在位置仅抖动约 1 个计数时，瞬时速度反馈也会出现 ±50，因此不再用速度寄存器必须接近零作为到位或停滞条件；速度仍显示供诊断。

某只尚未到位时，会列出其位置、目标、误差与速度；连续 2 秒没有继续接近时只读输出该舵机的目标寄存器、负载原码及解码后的驱动占空比、电压、温度与扭矩状态，连续 5 秒未满足到位条件则停止并卸力。位置误差 20 个计数仍然不能当作已到位。当前负载字段描述驱动占空比，不能直接当作实际力矩，也不能只凭一次停滞认定碰撞、供电不足或传感器边界问题。寄存器解释参考 [SC 舵机内存表](https://docs.waveshare.net/Memory_Map_Explanation/SC_Servo_Memory_Map_Explanation/)。

也可单次运行，或者只预览、只检查：

```powershell
# 只计算 Middle 的六个目标，不打开串口
& 'D:\miniconda\envs\lerobot\python.exe' 'D:\Desktop\CS\具身智能\lec3\作业\control_arm.py' middle --dry-run
# 只读检查路线，并列出正式运行时将解除的旧硬件限位
& 'D:\miniconda\envs\lerobot\python.exe' 'D:\Desktop\CS\具身智能\lec3\作业\control_arm.py' middle --check
# 执行一次移动，成功后保持
& 'D:\miniconda\envs\lerobot\python.exe' 'D:\Desktop\CS\具身智能\lec3\作业\control_arm.py' middle
```

控制前检查本次起点是否稳定、在记录区间内，输入是否为六个 0～1 数值。旧硬件限位不再用于拒绝路线，而是在正式运动前自动设置为完整原始范围；读回失败则不开始运动，仍尝试锁定 EEPROM 并关闭扭矩。配置时如果手臂位置改变，会用配置后的实测位置重新规划。跨越 1023/0 本身不再是拒绝条件。程序不修改编号或 `calibration.json`，保留六组端点与四个姿态。它不进行机械臂碰撞规划，分别可达的六个比例不代表组合后一定可达。

当前跨界改动验证的是软件规划和反馈跟踪，不是 SCS215 固件已验证的跨界能力。位置接口没有独立的跨界方向字段。如果这批舵机按普通线性位置误差反向驱动，分段程序会检测到反向并卸力，不能宣称仅靠取模就能成功穿过电位器的反馈空白区。本程序没有切换到 PWM 开环驱动模式。

同步位置和速度寄存器布局参考 [飞特官方 SCSCL Python 实现](https://gitee.com/ftservo/FTServo_Python/blob/main/scservo_sdk/scscl.py)。控制程序已做离线模拟测试，尚未运行真实机械臂。
