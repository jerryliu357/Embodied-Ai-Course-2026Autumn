# SCS215 机械臂 IK 课堂练习

使用助教仓库的 **SCS215 驱动 + NumPy 优化式 IK**，不需要 Placo。旧的 FK、IK 和 lec3 程序不变。键盘控制夹爪的空间位移，当前XYZ任务由前四个关节求解，ID5保持开始时的手腕旋转角，ID6保持当前开合。

## 运行

在 `D:\Desktop\CS\具身智能` 的 PowerShell 中执行，均使用 `lerobot` 环境：

```powershell
# 不连硬件，检查标定、模型和助教驱动
& D:\miniconda\envs\lerobot\python.exe "lec4\课堂练习\IK_SCS215\control_ik.py" --check

# 连接硬件，只读取；不会使能、卸力或改写配置
& D:\miniconda\envs\lerobot\python.exe "lec4\课堂练习\IK_SCS215\control_ik.py" --read-only

# 正常交互控制
& D:\miniconda\envs\lerobot\python.exe "lec4\课堂练习\IK_SCS215\control_ik.py"
```

默认按原转接板序列号寻找串口，需要时加 `--port COM9`。关闭其他占用串口的程序。

正常运行后，每行输入一条命令：

```text
speed 1
up 5
status
jog
```

`up 5` 表示相对于实测起点，沿固定底座坐标 **+Z 上移5cm**。`forward/back` 为前后 ±X，`left/right` 为左右 ±Y；`move 1 2 3` 表示前1cm、左2cm、上3cm的直线位移。`jog` 中 W/S、A/D、R/F 分别控制前后、左右、上下；默认每次1cm，`step 2` 可改为2cm，Q返回。运动中空格、Esc、Q或Ctrl+C停止并保持；运动按键不会积压。

启动不复位、不改变扭矩；第一条运动命令才使能六个关节。`stop` 停止并保持当前读数，`off` 关闭六只舵机扭矩（先托住机械臂），`quit` 关闭串口但保留目标及扭矩。普通跟随残差会减慢推进，不自动卸力；连续10秒没有可确认的末端前进，会取消剩余轨迹并保持当前读数。到终点后仍不能满足容差，会报告失败并保留最后的补偿目标。硬件异常、通信错误或用户停止会尝试保持，保持失败会明确提示。

## 标定与原理

- 标定直接读取 `settings/servo_info.json`，不复制多份。包括六组0/1端点、五个模型角度零位，以及夹爪闭合参考。ID3范围319～903、零位641；ID5范围400～976、零位688。
- 角度换算：`q = 方向 × (原始读数 − 零位读数) × 每计数角度`。内部用弧度。当前沿用330°/1024，尚未验证其物理精度；“576读数精确对应180°”会得到320°/1024。`config.json` 中 `degrees_per_count_override` 默认为null，确认后可设为例如0.3125，仅影响本程序。
- URDF 提供各关节的位移、旋转轴和连杆几何。将这些变换相乘得到正向运动学 `p=f(q)`。末端选 `gripper_frame_link`，不是随ID6开合移动的单个夹指尖；URDF的STL网格无需加载。
- IK 用雅可比矩阵将末端误差近似为 `JΔq`，求解 `min ||JΔq-e||² + λ²||Δq||²`，同时施加关节角范围约束；重新计算FK并迭代。阻尼用于抑制奇异附近的大幅关节变化，不是舵机PID。只约束位置，不强行固定夹爪朝向。
- 有效角度范围取标定与URDF限位交集，并对齐到整数读数。当前ID1～5有效原始范围分别为57～724、373～993、341～903、355～943、400～976。起点在外面时只提示，不自动强行复位。硬件限位另外只读核对；不自动写EEPROM或PID，也不把0/1023当成可循环跨越的角度。

执行器v3按以下流程工作：

1. 从当前反馈生成直线路径，默认每5mm规划一个IK节点。原始起点、终点及方向固定，不随反馈漂移。利用位置雅可比的零空间适当调整冗余关节，避开关节端点；必要时保持末端位置调整关节姿态。保持ID5的旋转角，避免为极小的位置收益把手腕旋转到限位。
2. 目标更新频率上限20Hz，每周期读取实际角度和FK末端位置。根据实际位置与当前参考的差距减慢轨迹推进：关节误差5～12计数、末端误差4～10mm之间逐步减速，超过上限暂停推进并继续纠偏；不是每个小点停车等精确到位。`speed`是速度上限，跟得慢时总用时会增加。
3. 每周期以规划关节角作为种子重新求解当前直线点，保持连续的关节解分支，防止从带有负载误差的实测角反复求解时姿态逐渐漂到限位。反馈通过实际角度、末端偏差和积分补偿纠偏：`b ← b + Ki·(参考−反馈)·dt`，下发`参考+b`。默认每关节补偿最多±30计数、每秒最多变化8计数。它在电脑端运行，不写舵机内部P/D或EEPROM；包含积分限幅、输出限位和防饱和。最终目标始终处于标定、URDF和硬件限位的交集内。
4. 使用助教 `FeetechMotorsBus.sync_write("Goal_Position", ..., normalize=False)` 同步发送改变后的目标，重复整数目标不重复写入；小数推进和补偿在内部累积。ID6保持运动开始时的开合。原始模式避免再次归一化取整，字节序、寄存器及通讯由助教驱动负责。
5. 终点要求对**名义IK参考**误差≤5计数，模型末端误差≤8mm，稳定至少0.4秒；另检查整个过程的横向偏差≤10mm。这些是当前验收阈值，不代表实物精度保证。因存在负载补偿，`Goal_Position`与反馈可能仍有差值，不能把这个差值当成名义目标的到位误差。连续命令保留有效的补偿状态，停止或卸力后重置。

屏幕的“实测沿向 X/50mm”是原始位置反馈经FK换算后，在指定运动方向上的位移投影；会反映落后或回退。倍率0表示参考暂时不推进，仍在纠正当前位置。显示100%不单独代表到位，最终结果还需通过以上检查。日志分别保存名义参考、实际下发、反馈、补偿量和真实执行用时。软件只在运动命令执行期间更新补偿，命令结束后的保持由舵机内部控制完成。

重启程序时，如果六个关节已经使能、位置稳定、目标偏移在补偿上限内且速度模式相符，会沿用现有保持目标，避免突然抹掉负载补偿而下沉。卸力状态或不符合条件时，仍先写当前位置目标再使能。

若原直线目标局部求解失败，打印“IK无解”，先尝试同一直线上的更短步长，再在关节约束内寻找保留正向分量的可行运动。发生投影偏移会明确报告，不冒充完成原直线；完全无法前进则保持。这里的“无解”表示当前局部求解未找到可接受解，不是对全局不可达的数学证明。本程序不包含碰撞检测。

## 验证与验收

```powershell
# 模拟已知起点、5计数死带，连续向上5cm，不连接串口
& D:\miniconda\envs\lerobot\python.exe "lec4\课堂练习\IK_SCS215\control_ik.py" --simulate --start-raw 381 455 764 837 675 104 --deadband 5 --command "up 5"

# 离线回归检查，不连接硬件
& D:\miniconda\envs\lerobot\python.exe "lec4\课堂练习\IK_SCS215\test_offline.py"
```

验收时在可达、无碰撞的姿态运行，按助教要求输入方向及厘米数，用尺子或固定参照物检查实际距离和直线程度，再演示jog。反馈坐标来自模型，不能代替实物测量。正常运行仅覆盖保存 `last_motion.json`；模拟覆盖 `last_simulation.json`，不产生按时间不断累积的日志。

2026-10-01 已在COM9的六关节实机执行v2：向上50mm，反馈模型估计上移50.56mm，最大横向偏差2.17mm，最终参考误差2计数，用时6.94秒；随后向下50mm，估计下移56.19mm，横向偏差5.64mm，最终参考误差4计数，用时7.81秒。原始起终点及目标保存在`tracking_validation.json`。这证明两次命令有实际关节反馈变化及反馈调速效果，不等同于用尺子验证了物理精度；向下测试仍有约6.3mm模型终点误差。测试结束保持使能，没有自动卸力。

## 文件与来源

`control_ik.py`：命令行和键盘；`robot_adapter.py`：标定转换、驱动和只读诊断；`ik_solver.py`：URDF FK/雅可比/优化；`trajectory.py`：直线规划、在线IK和反馈执行；`tracking.py`：反馈调速和有限积分补偿；`config.json`：运行参数；`test_offline.py`：离线测试。

`vendor/lerobot_EAI_SCS215` 保存[助教仓库](https://github.com/JyiDeng/lerobot_EAI_SCS215)固定提交 `bd2ee0bd961904090873d208fe79dc0ab3a4f863` 的六个必要驱动源码及Apache-2.0许可证，原文未修改，`SOURCE.json`记录校验值。仅本程序进程优先加载这些电机模块，其余工具模块复用已安装的LeRobot；不修改全局安装。使用底层SCS215总线接口，没有调用会配置PID并使能的 `SOFollower.connect/configure`。NumPy求解器复用了本项目旧IK的URDF数学部分并作优化，不宣称是官方Placo实现。
